Where this fits

This is step 2. It takes the numbers from Chart as a vector and learns to predict something about a person, such as whether they're an athlete. If charts carry no information about athletes, the model can't beat a model that knows only the birth date. The tool used in practice is LightGBM; the demo below is a small version of the same algorithm running in your browser.

Step 1: One tree is a set of yes/no questions

A decision tree splits people with questions like "Is Mars's longitude under 30°?" Each question is picked because it best separates the people the model is currently getting wrong. After a few questions, each group (a leaf) gets a score that nudges the prediction up or down.

Trees find combinations on their own. A second question asked only inside the first answer's group ("…and is the Moon in a water sign?") is an interaction, so no one has to list combinations in advance. This is the first tree the demo below learned:

Step 2: Boosting adds many small trees

One tree is crude. Boosting builds hundreds of them, each one fixing the mistakes left by the trees before it. For a yes/no outcome like "athlete", the model's score is a log-odds that turns into a probability.

Score after m trees: F_m(x) = F_0 + η · [ f_1(x) + f_2(x) + … + f_m(x) ] Probability: p = 1 / (1 + e^(−F)) Loss (log loss): L = −[ y · log p + (1 − y) · log(1 − p) ] For each person, before adding a tree: gradient g = p − y (how wrong, and in which direction) hessian h = p · (1 − p) (how sure the model already is) A split is chosen to maximize Gain = G_L² / (H_L + λ) + G_R² / (H_R + λ) − G² / (H + λ) (G and H are the sums of g and h in each group; λ keeps small groups from overreacting) Each leaf's score: w = −G / (H + λ) η (learning rate) shrinks every tree so no single tree dominates.

LightGBM speeds this up by sorting each feature into a few hundred bins and growing trees leaf by leaf. The demo uses 32 bins, trees 3 questions deep, η = 0.1 and λ = 1.

Step 3: Try it on simulated people

This demo makes 6,000 pretend people with real skies: random birth dates from 1900 to 1999, with planet positions computed for each one. The model sees 97 numbers per person: each planet's longitude and element, the separation of every planet pair, and the birth month and year. It then decides who is an "athlete" using rules you choose, so you know the truth in advance and can see whether the model finds it.

Chart effect: athletes are more likely when Mars is in a fire sign (Aries, Leo, Sagittarius) and the Moon is in a water sign (Cancer, Scorpio, Pisces). About 1 person in 16 has both. Season effect: people born January to March are more likely to be athletes, like the school-cutoff effect in real sports data. It has nothing to do with planets.

Step 4: How to read the result

  1. Only the gap counts. The baseline knows birth year and month. Turn the chart effect off and leave the season effect on: the full model scores well above 0.5, but no higher than the baseline. Season is doing all the work, and the stars add nothing.
  2. The shuffle test. Shuffling who is an athlete breaks any real link. Whatever score the model still gets is pure luck. On real data, retrain on about 200 shuffles and the real model has to beat all of them.
  3. Held-out people. All scores here are on people the model never saw. Training-set scores always look good and mean nothing.
  4. Replication. A real result has to show up again on a separate dataset, for example Gauquelin's records after training on Wikidata.

Step 5: Which chart factors did it use?

When the model beats the baseline, the next question is what it found. The bars show how much each feature improved the model in total (the summed split gain). In real analysis, SHAP values give a fairer version of this: for each person, they split the prediction into each feature's contribution, and those contributions add up exactly to the model's score.

SHAP: F(x) = average score + φ₁ + φ₂ + … + φₙ φᵢ = feature i's average effect on the score, over every order the features could be added in

With the strong chart effect on, "Mars in fire sign" and "Moon in water sign" should rise to the top. With it off, the importance list is mostly birth month plus noise.

On the real data

  1. Build the feature list from Chart as a vector for every person, about 380 numbers without birth times.
  2. Fit LightGBM to predict each occupation group, on the 70% exploration split, with early stopping chosen by cross-validation.
  3. Fit the birth-date-only baseline the same way, and report the held-out AUC gap with a 95% range.
  4. Repeat with shuffled labels within each birth year about 200 times, and give the share of shuffles that matched or beat the real gap.
  5. Show SHAP for any group that passes, then try to confirm it on the 30% hold-out and on a second dataset.
