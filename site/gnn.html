Graph neural network

A model that reads a chart the way an astrologer does: as planets connected by aspects, not as a flat list of numbers.

Test a claim 1. Chart as a vector 2. Boosted trees 3. Graph neural network

Where this fits

This is the alternative to boosted trees for step 2. Both try to predict something about people from their charts, and both face the same tests. The difference is the input: trees get one long row of numbers, while a graph neural network (GNN) gets the chart's structure, meaning which planets connect to which and how.

Step 1: A chart is a graph

In a graph, nodes are things and edges are links between them. Here each planet is a node, and each aspect is an edge.

Node i (a planet): x_i = [ cos λ, sin λ, sign one-hot (12), element (4), retrograde (1) ] Edge i–j (an aspect): type (conjunction, sextile, square, trine, opposition) strength s_ij = max(0, 1 − |θ − aspect angle| / orb) (from step 5 of Chart as a vector)

Planets sit at their place in the zodiac, and lines are aspects. Thicker lines are tighter aspects. Hover a line for details.

Step 2: Message passing

A GNN works in rounds. In each round, every planet collects a "message" from the planets it aspects, weighted by the aspect's type and strength, and updates its own description. The weights W are what the model learns.

Start: h_i⁽⁰⁾ = x_i Message: m_i = Σ over aspected planets j s_ij · W_type(i,j) · h_j⁽ᵏ⁾ Update: h_i⁽ᵏ⁺¹⁾ = ReLU( W_self · h_i⁽ᵏ⁾ + m_i ) After K rounds, pool the planets into one chart vector and predict: g = mean of h_i⁽ᴷ⁾ over all planets p(athlete) = σ( wᵀ [ g , birth year, birth month ] + b )

Each round lets information travel one more aspect. After one round, a planet "knows" about the planets it aspects. After two rounds, it knows about their aspects too, which is enough to see a T-square or a grand trine. Click a planet and move the slider to see how far its information reaches.

Step 3: Why it's a natural fit

  1. It sees patterns as shapes. A grand trine is a triangle of trine edges, and a T-square is an opposition with a square to both ends. A GNN can learn these from the structure instead of needing a hand-made "grand trine" flag.
  2. Order doesn't matter. Listing the planets in a different order gives the same answer, as it should.
  3. It grows easily. Adding the Ascendant, MC, lunar nodes, Chiron or asteroids just adds nodes and edges. The model's design doesn't change.
  4. Same weights everywhere. A "square" weight learned from Mars–Saturn is shared with every other square. That's a built-in assumption that aspects mean something by type, which is itself a testable claim. Separate weights per planet pair would test the opposite.

Step 4: The catch

GNNs have many more adjustable weights than trees and need much more data before they stop memorizing noise. On tables of a few hundred features and tens of thousands of rows, boosted trees usually match or beat neural networks. So the plan is to run the GNN after the trees, on the same split, and take it seriously only if it beats both the trees and the baseline on held-out people.

The same tests apply as on the trees page. Birth year and month go into the final step, so the model has a baseline to beat. Then come shuffled labels, held-out people and a second dataset. A GNN's flexibility makes these tests more important, not less.

On the real data

  1. Build one graph per person with PyTorch Geometric: planet nodes, aspect edges, and Ascendant and MC nodes when there's a birth time.
  2. Use a relational GNN (separate weights per aspect type), 2 or 3 rounds, small hidden size (about 32), dropout and early stopping.
  3. Train on the same 70% exploration split as the trees. Compare held-out AUC against the trees and the birth-date baseline.
  4. Run the shuffled-label test, at least 50 times given the training cost.
  5. For any group that passes, find which aspects mattered most, then confirm on the hold-out and a second dataset.

A realistic order is trees first, then a GNN only if the data grows to hundreds of thousands of charts, for example through Astro-Databank permission or site submissions.
